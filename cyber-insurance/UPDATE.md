# サイバー保険 比較表の定期更新手順

損保各社のサイバー保険・個人情報漏えい保険のパンフレット・約款を確認し、比較表（`index.html`）を更新する手順。定期実行のセッションはこの手順どおりに作業する。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `data/products.json` | 比較表の中身（各社の補償内容・資料リンク・特長、今回の変更点 `changes`） |
| `data/news.json` | 損保各社のサイバー関連情報（レポート、無料診断、商品改定、制度動向） |
| `data/sources.json` | 定期チェックする公式資料のURL台帳 |
| `data/sources_state.json` | 前回チェック時のハッシュ（`check_sources.py` が更新） |
| `check_sources.py` | 公式資料を取得し、変わったものを検知する |
| `build.py` + `template.html` | JSONを埋め込んで `index.html` を生成する |

## 対象範囲

- 日本損害保険協会「サイバー保険取扱い保険会社」掲載会社＋Chubb等の外資＋主な団体制度。
- **大同火災は対象外**（2026-11-26 ユーザー指示）。

## 手順

1. **変更検知**: `python3 cyber-insurance/check_sources.py` を実行し、`changed` / `new` / `failed` を確認する。
2. **変更があった資料を読む**: `cyber-insurance/.cache/` に保存された本体を読む。PDFは `pip install pymupdf` のうえ PyMuPDF でテキスト化する（poppler の pdftotext は日本語フォントが欠けて読めない）。旧値と比べ、変わった項目だけ `data/products.json` を直す。
3. **会社ごとの取得方法**（check_sources.py が自動で処理する。失敗したときの対処も記載）
   - **損保ジャパン**: 公式サイトはボット対策で自動取得を拒否する。ブラウザを装う等の回避はしない。公式パンフは信用金庫・商工会など第三者サイトに掲載されたコピー（sources.json）で取得し、新しい改定はWebSearchで「損保ジャパン サイバー保険 改定 pdf」を検索して新しい掲載先を探す。新しい掲載先のドメインは環境の許可ホストに追加が必要。
   - **東京海上日動のパンフPDF**: Tコンシェルはヘッドレスブラウザを拒否するので使わない。カタログ頁 → 頁内の「downloadPdfCatalog」リンクをセッションCookieつきでたどる（`flow: tcon`）。2027年始期版でカタログIDが変わったら、Tコンシェルで「サイバーリスク保険」を探して URL を差し替える。公式ページが時々400を返すが、再試行と翌月の実行で拾えれば問題ない。
   - **共栄火災**: サーバーが中間証明書を送らないため、`certs/cybertrust-sureserver-ev-ca-g3.pem`（crt.sh で取得、有効期限2029-05-29）をシステムのCAに足して検証する（`extra_ca`）。検証は無効にしない。期限切れや発行元変更で失敗したら crt.sh で新しい中間証明書を取得する。
   - **ニュースリリース**: 各社のニュース一覧は「サイバー」「情報漏」を含む行だけ監視し、新着行を報告する（`keywords`）。保険会社自身の情報漏えい事故の告知も拾うが、比較表の関連情報には商品・サービス・調査に関するものだけを載せる。
   - **代理店システム**: 代理店ログインが必要な資料はクラウドからは取得しない。ユーザーがデスクトップ版Claude Codeでログインしたブラウザから取得したPDFを `cyber-insurance/inbox/` に置いた場合は、それも読み込む（代理店限定の内容は比較表に転載しない）。
4. **新しいパンフ・約款の発見**: 各社の商品ページに新しいPDFリンク（新しい始期・改定年月）が出ていれば `data/sources.json` に追加し、古いものは残すか差し替える。新商品・新規参入会社も検索で確認する（日本損害保険協会の取扱会社一覧が起点）。
5. **関連情報**: 前回以降の損保各社のサイバー関連リリース（レポート、無料診断、商品改定、制度動向）を検索し、`data/news.json` の各カテゴリ先頭に追加する。1年以上前の項目は落としてよい。
6. **変更点の記録**: `data/products.json` の `checked_at` を今日の日付にし、`changes` を今回の差分で置き換える（差分がなければ空配列）。
7. **ビルドと公開**: `python3 cyber-insurance/build.py` → コミット → 作業ブランチへ push。公開ページ（Artifact）も同じ `index.html` で更新する。

## 記載ルール

- 値は公式資料の記載に基づく。確認できない項目は「未確認」とし、推測で埋めない。前回値を残すときは「未確認（旧表: …）」と書く。
- ○△× は先頭に付ける（○=補償対象、△=条件付き、×=対象外）。
- フォレンジック発動要件の3行（社内発見／公的機関・委託ベンダー通報／その他第三者通報）は各社で差が出やすいので、要件の文言（「外部通報」の定義など）を必ず確認する。
- 代理店運営の商品特設サイト（cyber-protector.com、ad-cybersecurity.com）は保険会社の承認番号つきの募集文書だが、公式サイトではない点を資料欄に明記する。

## 必要なネットワーク許可

クラウド環境の許可ホストに、`data/sources.json` の各ドメインが入っていること（2026-11-25 に追加済み）。新しいドメインの資料を追加したら、環境の許可ホストにも追加が必要。
