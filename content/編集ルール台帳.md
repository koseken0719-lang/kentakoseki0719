# 編集ルール台帳（修正指示の条件化・蓄積管理）

運用：著者から修正指摘を受けるたびに、ここに「候補」として記録→納品時に「編集ルールへの追加候補」として提示→**著者が承認した条件のみ「承認済」**にして文体ガイド/編集基準へ反映する。一度きりの好み・特定記事限定の指摘は「単発」とし、恒久ルール化しない。

## 指摘→条件の変換表（基本対応・編集指示書②より）

| 著者の指摘 | 制作条件への変換 |
|---|---|
| AIっぽい | 段落の役割と順序を確認し、同じ構成を機械的に繰り返さない |
| きれいすぎる | 著者固有の発言や経験を優先する |
| 何が言いたいのか分からない | 記事の中心となる主張を1つに絞る |
| 内容が薄い | 一般論ではなく、具体的な状況や判断の根拠を加える |
| 営業っぽい | 不自然なサービス紹介や問い合わせ誘導を追加しない |
| くどい | 同じ意味の説明を繰り返さない |
| もっと経営者目線で | 経営者が直面する具体的な判断や悩みに結びつける |
| 勝手に変えないで | 指定箇所以外の文章・構成は変更しない |

※全記事への無条件適用はせず、記事の目的と文脈で判断する。

## 修正作業の範囲規律（常時適用）

- 誤字脱字の修正依頼なら、誤字脱字だけを直す
- 冒頭の修正依頼なら、本文や結論は変更しない
- 見出しの修正依頼なら、本文は変更しない
- 構造変更の依頼でも、著者固有の言葉は可能な限り維持する
- 記事全体の再構成は、明示的な指示があった場合のみ
- 範囲外に問題を見つけたら、勝手に直さず別途提案する

## 失敗の3分類（原因欄に使う）

①空白を勝手に埋めた（創作・補完）／②著者の個性を均した（一般表現への置換）／③単発思考（次回への蓄積を怠った）／④その他
